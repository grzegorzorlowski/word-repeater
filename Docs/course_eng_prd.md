# Product Requirements Document (PRD) – 10x-cards

## 1. Product Overview

The 10x-cards project aims to enable users to quickly create and manage sets of educational flashcards. The application leverages LLM models (via API) to generate flashcard suggestions based on provided text.

## 2. User Problem

Manually creating high-quality flashcards requires significant time and effort, discouraging users from using the effective learning method of spaced repetition. The goal of this solution is to reduce the time needed to create suitable questions and answers and to simplify the process of managing learning material.

## 3. Functional Requirements

1. **Automatic Flashcard Generation:**

   * The user pastes any text (e.g., a textbook excerpt).
   * The application sends the text to an LLM model via API.
   * The LLM model proposes a set of flashcards (questions and answers).
   * Flashcards are displayed to the user in a list view with options to accept, edit, or reject them.

2. **Manual Creation and Management of Flashcards:**

   * A form for manually creating flashcards (front and back).
   * Options to edit and delete existing flashcards.
   * Manual creation and display within the “My Flashcards” list view.

3. **Basic Authentication and User Accounts:**

   * Registration and login.
   * Option to delete the account and all related flashcards upon request.

4. **Integration with Spaced Repetition Algorithm:**

   * Provide a mechanism to assign flashcards to a review schedule (using an existing algorithm).
   * No additional metadata or advanced notification features in the MVP.

5. **Storage and Scalability:**

   * Flashcard and user data stored securely and in a scalable manner.

6. **Flashcard Generation Statistics:**

   * Collect data on how many flashcards were generated by AI and how many were ultimately accepted.

7. **Legal Requirements and Restrictions:**

   * User and flashcard data stored in compliance with GDPR.
   * Users have the right to view and delete their data (account and flashcards) upon request.

## 4. Product Boundaries

1. **Out of Scope for MVP:**

   * Advanced, proprietary spaced repetition algorithm (use an existing open-source library).
   * Gamification mechanisms.
   * Mobile applications (web version only).
   * Importing multiple document formats (PDF, DOCX, etc.).
   * Publicly accessible API.
   * Flashcard sharing between users.
   * Advanced notification system.
   * Advanced keyword-based flashcard search.

## 5. User Stories

**ID: US-001**
**Title:** Account Registration
**Description:** As a new user, I want to register to have access to my own flashcards and be able to use AI-powered flashcard generation.
**Acceptance Criteria:**

* The registration form includes fields for email address and password.
* After correctly filling out the form and verifying the data, the account is activated.
* The user receives confirmation of successful registration and is logged in automatically.

---

**ID: US-002**
**Title:** Logging into the Application
**Description:** As a registered user, I want to log in to access my flashcards and generation history.
**Acceptance Criteria:**

* After entering valid login credentials, the user is redirected to the flashcard generation view.
* Invalid login credentials trigger an appropriate error message.
* Login data is stored securely.

---

**ID: US-003**
**Title:** AI-Based Flashcard Generation
**Description:** As a logged-in user, I want to paste a text passage and generate suggested flashcards with a button to save time on manual creation.
**Acceptance Criteria:**

* The flashcard generation view includes a text box where the user can paste text.
* The text box accepts between 1,000 and 10,000 characters.
* After clicking the generate button, the app communicates with the LLM API and displays a list of generated flashcard suggestions for review.
* If there is an API issue or no response, an appropriate error message is shown.

---

**ID: US-004**
**Title:** Reviewing and Approving Flashcard Suggestions
**Description:** As a logged-in user, I want to review generated flashcards and choose which ones to add to my deck to keep only useful questions and answers.
**Acceptance Criteria:**

* A list of generated flashcards is displayed below the generation form.
* Each flashcard has buttons for approval, editing, or rejection.
* After selecting desired flashcards, the user can click save to add them to the database.

---

**ID: US-005**
**Title:** Editing Manually Created and AI-Generated Flashcards
**Description:** As a logged-in user, I want to edit created or generated flashcards to correct mistakes or tailor them to my needs.
**Acceptance Criteria:**

* A list of saved flashcards (both manually created and AI-approved) is available.
* Each flashcard can be clicked to enter edit mode.
* Changes are saved to the database upon confirmation.

---

**ID: US-006**
**Title:** Deleting Flashcards
**Description:** As a logged-in user, I want to delete unnecessary flashcards to keep my deck organized.
**Acceptance Criteria:**

* Each flashcard in the “My Flashcards” view has a delete option.
* The user must confirm before a flashcard is permanently deleted.
* Flashcards are permanently removed from the database upon confirmation.

---

**ID: US-007**
**Title:** Manual Flashcard Creation
**Description:** As a logged-in user, I want to manually create flashcards (defining front and back) to add my own content not generated automatically.
**Acceptance Criteria:**

* The “My Flashcards” view contains a button to add a new flashcard.
* Clicking the button opens a form with “Front” and “Back” fields.
* After saving, the new flashcard appears in the list.

---

**ID: US-008**
**Title:** Study Session with Spaced Repetition Algorithm
**Description:** As a logged-in user, I want my added flashcards to be available in a “Study Session” view based on an external algorithm, so I can learn effectively using spaced repetition.
**Acceptance Criteria:**

* In the “Study Session” view, the algorithm prepares a learning session with flashcards.
* The session starts by displaying the front of a flashcard; upon interaction, the back is revealed.
* The user rates how well they remembered the flashcard according to the algorithm’s expectations.
* The algorithm then presents the next flashcard in the session.

---

**ID: US-009**
**Title:** Secure Access and Authorization
**Description:** As a logged-in user, I want to ensure that my flashcards are not accessible to other users to maintain privacy and data security.
**Acceptance Criteria:**

* Only logged-in users can view, edit, and delete their own flashcards.
* No access to or sharing of other users’ flashcards.

---

## 6. Success Metrics

1. **Flashcard Generation Efficiency:**

   * 75% of AI-generated flashcards are accepted by users.
   * Users create at least 75% of new flashcards using AI-generated content.

2. **Engagement:**

   * Track the number of generated flashcards compared to the number of approved ones to analyze quality and usefulness.
